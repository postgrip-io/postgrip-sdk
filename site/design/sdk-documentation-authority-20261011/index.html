    Target ownership

    AGENTS.md is concise mandatory guidance plus links. docs/index.md is the current owner map. Development guides own architecture, contracts, checks and PR process. Authentication, configuration, cURL, bootstrap, live scenarios, releasing and consumer migration retain focused owners. Language guides own language-specific examples/replay; local CLAUDE/AGENTS files route to owners.

    Historical unification proposals, phase reports and the dated simplification report move under docs/archive/, with preserved results and a clear historical banner. Old URLs get short routing stubs; current navigation points directly to the archive index. Release notes remain explicitly historical. Still-current release/rollback requirements remain in releasing/migration; archiving an old BLOCKED report neither clears a release gate nor claims deployment success.

    Web owns canonical HTTP contracts and its SDK pin/discovery procedure. SDK owns mirrors, generated clients and published artifacts. Cross-link owners. Web is the sole owner of the shared PR review lifecycle; SDK contributing documents its local application and checks rather than copying that lifecycle. Keep the compatibility Go module path. Correct repository/Pages URLs to the verified postgrip-sdk name without rewriting immutable historical evidence. Do not move SDK source pins for prose-only changes.

    SDK workflows currently use GitHub-hosted runners and run full CI for docs. Web's self-hosted pool, path selection and enforcement are not SDK facts. Document these differences rather than claiming synchronization by copying inaccurate CI prose. Workflow behavior changes are a separate scope.

    Focused delivery slices

    1. Governance: concise root entry, current owner map and four development guides.
    2. History: archive original records, preserve links and current release gates; replace duplicate contributor/placeholder guidance with owner links.
    3. Usage: fix current language setup/examples, current reference routing and documentation-site URLs; remove duplicated release/configuration claims.
    4. Web: reciprocal SDK-owner links and verified repository naming in its current contract and linked coverage guides; record cross-repository bytes.
    5. Closure: audit every disposition, reconcile shared review-process ownership and record validation counts, findings and explicit limits separately.

    Each slice follows the review loop in development/contributing.md: a scoped PR, self-review, Codex review, validated fixes, green CI and squash merge.
