    SDK guidance recursive reference audit

    Date: 2026-10-12 (America/Los_Angeles). Reproducible SDK baseline: 0ea347918a2e87bbcc7df7103f414da241766893. The initial checkout also included PR #69's proposal at eb63e55c. That revision differs from the baseline only in docs/design/contract-driven-sdk-layering.md; the SDK source and baseline inventory below are identical. The proposal was reviewed as an unmerged design, and this guidance PR was branched independently from the baseline on main. This is maintenance evidence for the guidance design, not another policy owner or a claim of runtime/release readiness.

    Scope and traversal

    The baseline inventory contains 66 tracked Markdown files outside docs/reference/, docs/archive/ and docs/design/: 52 current guides/entry points, 10 historical routing stubs, three release-note histories and one generated operation-coverage report. Every file has a disposition below. The archive index was also read to verify its non-normative boundary.

    The recursive link walk starts at AGENTS and resolves relative links, same-repository GitHub URLs, published language-site URLs and Go Jekyll relative_url links. It reaches 36 inventory files; the remaining 30 are included explicitly, covering site-navigation pages, example guides and contributor/test entry points. The inventory therefore does not depend on a page being reachable by an inline Markdown link. After corrections, the 66 files contain 203 resolved local reference edges with no missing destinations. The unmerged transport design is linked through PR #69 so this guidance can be reviewed independently from main.

    Current guides were compared for agreement on ownership, MVC-ish roles, contracts, language/package support, authentication, configuration, validation and the PR/release process. This is a documentation-consistency audit with focused source verification, not an exhaustive correctness audit of every runtime method mentioned by the guides.

    Historical archive contents, release history and past acceptance records are terminal evidence, not current instructions to rewrite. Active designs are proposals checked for status and consistency with current owners; they do not establish delivered behavior. Generated current API pages are checked by the generator and reference validators, not claimed as 181 independent manual runtime reviews. Old immutable bundles retain their historical URLs.

    External registry, language/tool documentation, release pages and unrelated web product/deployment guides are external references, not SDK policy owners. This audit does not claim to review all documentation in other repositories or verify registry publication and live service behavior.

    Corrections and source evidence

    Conflicting or incomplete claim Correction and evidence
    MVC-ish had no explicit SDK mapping or review checklist Architecture now defines models, orchestration, bindings, adapters and composition with Go/TypeScript/Python mappings. Generated schema/binding colocation is distinguished from handwritten mixed responsibilities.
    All root constructors share precedence Configuration, root README and Go/TypeScript introductions now agree with Go New/NewFromEnv, TypeScript resolvePostGripConfig and Python resolve_config.
    Omitting an Agent URL always selects the cloud default All three installation guides now account for plane and common environment fallbacks in Go NewConnection, TypeScript Connection.create and Python Connection.__init__.
    A root token implies management-only Agent credentials Authentication and root README describe Go/Python environment credential selection and TypeScript runtime configuration, following the Agent constructors and request auth-lane selection.
    Common timeout/retry behavior is already implemented Configuration describes current root forwarding and plane eligibility; the proposed transport design remains separate.
    All Agent HTTP failures use the structured error base TypeScript/Python API guides and authentication now match their Connection error paths and PostGripAgentError subclasses. TaskFailedError carries task ID/message, not an underlying ApplicationFailure field.
    Go package arrows and shared transport ownership were unclear Package guide arrows now mean consumer-to-dependency and include go/internal/transport, checked against production imports.
    Node/npm alone runs the repository build TypeScript installation identifies bun run clean inside package.json's build script.
    Numeric Service retry caps belong to OpenAPI Go Service guide attributes numeric caps to client.go; the contract annotations govern eligibility.
    Adding a fourth language conflicts with a fixed three-artifact rule Architecture and releasing distinguish current support from required future generator, validation and release integration.
    Closed schemas exclude explicitly declared maps Contract guidance preserves canonical open-ended fields, matching additionalProperties in the mirrors.

    Other retained guides agree with these topic owners at the reviewed policy boundaries. Runtime guides keep language-specific workflow mechanics; fixture and release guides keep their explicit consent and evidence requirements.
