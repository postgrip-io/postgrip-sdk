    Corrective review

    The PR review raised two genuine blockers. Both source-code deviations are now corrected:

    1. Agent task and workflow histories no longer require unbounded HTTP responses. The server captures a stable snapshot boundary in an opaque, resource-bound cursor and constrains pages by event count and serialized bytes. SDK full-history methods follow cursors, while walkers/async generators/iterators permit bounded incremental consumption.
    2. Live tiers are executable rather than labels. The fixture manager enforces exact contract ownership, run-prefixed resources, explicit IDs, triple-consent destructive calls, reverse cleanup, secret redaction, and a durable ledger. Workflows schedule nightly and production runs and gate all releases on isolated pre-release coverage.

    A later Codex pass found six additional source-level regressions. All were valid under the approved design and are corrected without weakening its auth boundaries:

    1. Legacy Agent runtime session families are revoked rather than refreshed without their original namespace, queue, and signing-key bindings.
    2. The dashboard unwraps and follows paginated Agent event pages.
    3. The Agent CLI reads the standard message error field with legacy fallback.
    4. postgrip agent up consumes an administrator-issued one-time enrollment key; the tenant management token remains management-only.
    5. Previously applied migration 0136 is restored byte-for-byte so deployment checksum validation remains stable.
    6. TypeScript managed-runtime signing loads Node crypto only when signing is configured. A browser-target root-facade bundle and eager-graph regression prove Worker-style runtimes do not need Node compatibility.

    While rebuilding the evidence, ignored output from the pre-consolidation npm layout was also found in the local dist tree. TypeScript builds now clean that tree before compiling, preventing stale files from entering an artifact.

    A fresh Codex pass found four more valid, design-compatible deviations. They are corrected in the coordinated PRs:

    1. Go sandbox WebSocket handshakes now reuse the shared redirect-safe HTTP client, so same-host redirects to a different port or subdomain cannot receive management or gateway credentials. Explicit separately configured relay origins remain supported.
    2. All terminal/runtime Agent API consumers prefer the standard message error field while retaining error as a legacy fallback.
    3. The internal global-administration contract now includes fleet rollout GET/POST/DELETE operations, and its checker enforces reverse server-route coverage.
    4. Common agent:operate tokens can no longer reach undocumented Agent host update, lifecycle, targeted-placement, or security-settings mutations. High-impact host actions require an owner/admin session; ordinary member check and poll probes remain compatible.
    5. Every remaining undocumented Agent GET route that exposes host, credential, configuration, or browser-only history state now requires an organization member session. The Agent contract checker enforces reverse coverage so a future non-contract management route cannot silently inherit common-token access.
    6. Migration-0140 recovery now has an explicit owner/admin rotation grant: a fresh key is bound atomically to the same tenant and Agent ID only when the caller supplies the current key hash. The old key and sessions are revoked, stale/cross-tenant/replayed grants fail closed, and normal enrollment still rejects a mismatched key.
    7. Image-backed managed runtimes accept the host-injected delegated refresh credential and omit the variable when none is issued. The credential is still unavailable to shell payload allowlists and is never replaced by the common management token.

    The next SDK review found four further deviations. Each was independently checked against the immutable design and corrected in db1c7827643fb40c008573343635f093dbc7b69f:

    1. Python sandbox WebSocket redirects now compare the destination origin before constructing the redirected handshake, so arbitrary gateway headers cannot cross origins on any supported websockets>=13 release.
    2. Live targeted operations must contain the exact identifier recorded for their declared fixture resource; merely naming an existing ledger key is no longer sufficient.
    3. TypeScript runtime signatures cover the final request pathname and query, including a configured reverse-proxy prefix.
    4. TypeScript relay scheme matching is case-insensitive as required by URL semantics.

    The same design audit corrected one adjacent error-envelope mismatch: TypeScript Agent errors prefer the standard message field and use error only as a legacy fallback.

    The final SDK review found four valid design deviations, all corrected in 9e35ddf2a4fbe68ec8cb3f73f6f01bb96576da14:

    1. Fixture ownership is checked against target path parameters only, so an identifier elsewhere in a request cannot authorize mutation of another object.
    2. Cleanup requests are fully resolved and frozen when their resource is registered, preventing later captures from redirecting cleanup.
    3. Creation intent is persisted before execution and finalized immediately from resource captures, before any unrelated response capture can fail.
    4. Generated raw Python examples refuse redirects instead of forwarding the management bearer. The same final design audit applies explicit redirect refusal to the Go and TypeScript examples, and static documentation checks enforce all three guards across 121 generated examples.

    The live gate cannot honestly be marked PASS in this change. GitHub currently has only github-pages, npm, and pypi environments; no disposable URLs, scenario secrets, host-runtime credentials, or live run evidence are available. Recorded tests and fixture-manager self-tests are not substituted for that evidence.
