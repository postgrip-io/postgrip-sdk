    Deviations and corrective actions

    The first TypeScript test run exposed old HTTP fixtures that did not opt into the newly shared insecure-development control. The fixtures now set that control explicitly, and all HTTPS enforcement plus native tests pass.

    The first Python wheel dry run retained an obsolete postgrip_agent tree from a pre-move build directory. The build output was removed, the wheel was rebuilt from a clean tree, and a content assertion now rejects all three obsolete module prefixes.

    After the protocol move, the drift checker initially scanned go/protocol as if it were an SDK mirror and its GitHub fallback self-test still expected the old path. The checker now excludes the source-of-truth directory from the alias audit, tests the new path, and passes both self-test and monorepo modes.

    The package audit found duplicated URL/token validation and safe-redirect setup in the Go management clients. These mechanics moved to go/internal/transport; TypeScript and Python received equivalent private configuration modules. Plane-specific request behavior remains in each plane adapter as required by the design.

    A later transport review found three additional cross-language mismatches. Python sandbox connections now reject a redirected WebSocket origin before a handshake can forward arbitrary gateway headers across the complete supported websockets>=13 range. TypeScript signs the final URL path, including a configured reverse-proxy prefix, and treats URL schemes case-insensitively. The TypeScript Agent adapter also prefers the standard message error field while retaining error only as a compatibility fallback. These corrections are recorded in db1c7827643fb40c008573343635f093dbc7b69f.

    No unresolved Phase 2 deviations remain.

    Remaining risks

    • The coordinated server modules use a local replacement until the SDK branch is pushed. Phase 5 pins the resulting remote pseudo-version and reruns the same server suites without local replacements.
    • Registry ownership and coordinated server deployment remain the release risks recorded in Phase 0; no package publication is attempted by this work.
