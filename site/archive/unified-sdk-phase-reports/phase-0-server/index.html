    Deviations and corrective actions

    The design originally conflicted with the host runtime's deliberate omission of delegated refresh tokens. Inspection showed that refresh rotation discarded delegated namespace, queue, and signing-key claims. The server now persists and reapplies those bindings, restores the normal short access-token TTL, and only then injects the refresh token. Tests prove a rotated delegated session cannot escape its namespace and retains its ephemeral signing identity.

    The first implementation also retained production fallback to the old Agent management-token table. That contradicted the one-token boundary. PostgreSQL- backed Agent authentication now accepts only the common control-plane record; the old path remains solely for in-memory test/development compatibility.

    Post-review validation found that pre-migration runtime-session rows lacked the delegation bindings needed for safe refresh. Migration 0140 now revokes those legacy families, and both in-memory and PostgreSQL rotation reject any unbound row. Fresh enrollment persists the Agent's explicit namespace, queue, and signing-key bindings. The same corrective revision restores migration 0136 byte-for-byte, follows paginated Agent event logs in the dashboard, reads the standard error envelope in the CLI, and makes agent up consume a separately issued one-time enrollment key instead of trying to turn a tenant management token into a runtime credential.

    A subsequent review found three more server deviations. Every terminal/runtime Agent client now consumes the standard error envelope; the internal global-admin contract includes all fleet rollout routes and is checked in both directions; and common tenant tokens are excluded from undocumented Agent host administration. Owner/admin sessions remain required for update, upgrade, helper, and trust-state actions, while ordinary member check/poll probes remain available. The same session boundary covers targeted host placement and security-log configuration without changing documented public Agent operations.

    The next review found three further deviations at the same boundary. All undocumented host inventory, credential inventory, metrics/config, and browser-only history routes now require an organization session, with a reverse router-to-contract check preventing future common-token exposure. A targeted owner/admin enrollment-key rotation preserves the existing Agent ID, tenant, placement, and relationships while atomically revoking its old key and sessions; this restores the documented migration-0140 fresh-key recovery path without relaxing normal enrollment binding. Finally, image-backed managed runtimes accept the delegated POSTGRIP_AGENT_REFRESH_TOKEN that the host already injects, while shell allowlists and the common tenant token remain unchanged. The public Agent contract and migration chain are byte-identical.

    No unresolved Phase 0 implementation deviations remain.
