# Check worker connectivity and trust

`POST /api/v1/workers/{workerId}/check` · `checkWorker` · Worker

> Contract bundle `a2eca93ec7015c79105e06ba2940c0c83bb0dae39b30e720036c09aa5e1d7837`
> Worker contract `86004c9dd3c7b8cf629e47141a53e4fcfb97f633294b96a68bec1c67f957fcce`

PostGrip asks the Worker to re-attest, then computes the check result from its own records: the Worker's trust record and the attestation the orchestrator verified and recorded while the check ran. The Worker's answer only signals that its attempt finished; nothing in it reaches the result or the audit record.

Errors use the stable JSON envelope `code`, `message`, `requestId`, and optional `details`.
The `requestId` is safe to include in support and audit workflows; never log the bearer token.
