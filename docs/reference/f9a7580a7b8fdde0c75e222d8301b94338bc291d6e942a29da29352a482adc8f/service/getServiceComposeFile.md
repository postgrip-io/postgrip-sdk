# Get an environment Compose override

`GET /api/v1/services/project/{serviceId}/environments/{environmentId}/compose` · `getServiceComposeFile` · Service

> Contract bundle `f9a7580a7b8fdde0c75e222d8301b94338bc291d6e942a29da29352a482adc8f`
> Service contract `37484d91ca60df1f18de9d8d4b1f8b8931e108212372a2c829e673fd83c9191b`

Returns the Worker-held Compose override for an exact service environment. For the production environment of a service built with Docker (including ZVEC and LadybugDB), when the Worker has no file, or still has an earlier file PostGrip generated, the read first writes PostGrip's generated starter file to the Worker and returns it. Otherwise an environment with no file answers an empty `content`.

| --- | --- | --- | --- |
| `200` | Successful response | `application/json` | `ServiceComposeFile` |
| `404` | Not found. `SERVICE_NOT_FOUND`: `serviceId` or `environmentId` is not a UUID, or names no service or environment of the tenant. | `application/json` | `ErrorResponse` |

## Behavior and lifecycle

Returns the Worker-held Compose override for one exact service environment. The content can contain sensitive inline configuration.

- Do not log Compose content and use a protected output file when persisting it.
